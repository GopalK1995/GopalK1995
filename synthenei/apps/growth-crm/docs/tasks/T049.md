Done:
- Connector `slack` (src/lib/connectors/slack/**, registered in connectors/all.ts). OAuth v2 (bot token, scopes chat:write, channels:read, groups:read, channels:join; comma-list `scope` via extraAuthParams) through the connector core; the token lives in the Vault. Slack bot tokens do not expire, so there is no refresh.
- Channel picker (assets.ts, server-action targets): `listSlackChannels` returns names/ids/privacy only; `selectSlackChannel` re-checks the id against what Slack reports for THIS token, joins a public channel the bot is not in, stores channel + alert switches + team + `include_names` + locale in the connection's Vault bundle and the signing secret in the webhook bundle, heals a connection that was parked for a lost channel, and is audited (`slack.channel_selected`; audit or nothing). `sendSlackTest` posts a test alert.
- Alerts: event fan-out extension (jobs.ts, `registerFanout`) turns `lead.created` (new enquiry), `lead.sla_breached` (SLA breached), `payment.paid` (advance received) and `connector.sync.failed` (sync failed) into one `slack.alert` job per runnable Slack connection of the event's workspace (queue connector_sync). Events outside those four cost nothing. The handler (deliver.ts) re-checks the workspace, the switch and the channel, applies a per-connection cap (30/min, a flood from an import is dropped not sent), builds the message and posts.
- Privacy: the default alert shows source, city/status or amount and a link, never a person's name; names appear only when the owner turned `include_names` on. Every data string is escaped (mrkdwn) or defanged (plain text, fallback) so a lead name cannot ping `@channel` or inject a link. Buttons only for an https link built from `APP_BASE_URL` (no base = no button).
- Revoked token: Slack's `token_revoked | invalid_auth | account_inactive | ...` -> CredentialError -> connection `needs_attention` with a readable `last_error`, `connector.sync.failed` event (best effort), and no further posts until the owner reconnects. A deleted/archived channel parks it the same way; `not_in_channel` rejoins once. Slack `ratelimited` retries on the queue backoff. Signed Events API deliveries (`tokens_revoked`, `app_uninstalled`) park the connection at once; the team id in the body must equal the connection's team (the signing secret is shared by every tenant of the platform app).
- Signed request verification: `signature.ts` (v0 HMAC-SHA256, 5 minute window, constant time, reasons) pinned to Slack's published vector and checked against the T023 edge verifier. Block builder: `blocks.ts` (header, fields, context, link button, Slack's length/count limits).
- Sandbox / showcase: mock gateway (token `slack-mock-token`, or APP_ENV=demo without credentials), no network, refused in production. `SLACK_API_BASE` points the client at a stub.
- Zapier private app (integrations/zapier-app, Platform CLI format): custom auth (CRM URL + API key, tested with GET /api/v1/me); six REST-hook triggers (New Lead, Lead Status Changed, New Deal, Deal Stage Changed, Deal Won, Payment Received) subscribing through POST /api/v1/webhooks and unsubscribing through DELETE, with sample lists from the list endpoints; actions Create Lead, Update Deal (PATCH) and Move Deal to Stage (reads the version, then POST move). Idempotency keys on subscribe and create.
- Make custom app (integrations/make-app, component layout of the Make Apps extension): connection (CRM URL + API key, checked with /me), six dedicated webhooks + instant triggers (attach = subscribe, detach = delete), the same three actions. Shared catalogue in src/lib/connectors/automation/catalog.ts; `connector.ts` there registers `zapier` and `make` (auth none, no streams) so they show in the integrations list.
- Strings: namespace `slack` (en, ta draft, in _review.json) registered in src/i18n/registry.ts; `slack.sandbox`, `zapier.sandbox`, `make.sandbox` in integrations.json. Env names in .env.example, no values.
