T046 · OTA via channel manager + iCal fallback · BUILT, NOT RUN AGAINST ANY OTA OR DATABASE

Done:
- `ChannelManager` adapter interface (`channel-manager/types.ts`): `test`, `listChanges` (pull, cursor), `parseWebhook` (push, already signature-verified), `pushAvailability` (full picture, idempotent). Reservations in (created / modified / cancelled) become `booking` custom-object records through the external-link dedupe (`apply.ts`): idempotent (content hash), older versions never overwrite newer ones, a cancel for a reservation never seen creates nothing, a cancelled booking is never resurrected, compare-and-set on `records.version` with one retry. Records are labelled OTA (`source_ota`, raw `ota_channel`) with commission (percentage as sent, or derived from the exact amount; amounts in major units, never invented; unreadable rows are rejected with a reason, not guessed). `booking.created|cancelled` events, no PII in titles, samples or events.
- ONE generic adapter shell (`generic.ts`) speaking a neutral documented JSON contract (no vendor named, partner not chosen, B-6) with synthetic fixtures (`fixtures.ts`, a scripted `fixtureHttp()` with paging). Connector `channel-manager` (registered in `all.ts`): streams `reservations` (every 15 min, safety net behind webhooks) and `availability` (every 30 min, pushes closed ranges per room only when they changed), webhook parse + apply, sandbox token `cm-fixture-token` (or `APP_ENV=demo` without a key) serves fixtures with no network and is refused in production.
- Availability out (`availability.ts`): confirmed bookings of any origin become merged closed ranges per room (a cancel reopens the range by simply disappearing from the snapshot); rooms without a room value close nothing and are counted.
- Generic iCal fallback (`ical/**`, connector `ical`, no approval): RFC 5545 parser (unfolding, any line end, quoted params, TEXT escapes, DATE / UTC / TZID / floating, DURATION, STATUS, SEQUENCE, LAST-MODIFIED, nested components skipped, recurrence rejected not guessed, event and size caps); stays with exclusive all-day DTEND = check-out, time-zone conversion on Intl (DST safe, unknown TZID falls back to the property zone with a warning); UID dedupe, newest SEQUENCE wins; STATUS:CANCELLED and UID vanishing both cancel; a feed that suddenly lists nothing is a failure, not "everything cancelled"; read-only towards Airbnb / Booking.com; only dates and kind are stored (summary and description, which carry guest details, are dropped); past events are not imported; poll every 30 minutes.
- SSRF-safe fetch (`ssrf.ts` + `fetcher.ts`): https only, hostnames only (no IP literal, no userinfo, port 443 only, no internal-looking names), the address actually connected is checked in a custom DNS lookup (a mixed or rebinding answer is refused), every redirect re-validated (max 3, never to http or a private host), 2 MB cap (header and stream), 10 s deadline, no compression, IPv4 and IPv6 classification including mapped, NAT64 and 6to4 forms.
- Export feed (`export.ts`): blocked dates of ONE property as text/calendar behind a 256-bit per-property token (only the SHA-256 is stored; plaintext shown once); optional per-channel token that leaves that channel's own bookings out; dates only ("Not available"), merged ranges, other rooms, cancelled and other tenants excluded; unknown, malformed or revoked token gives one identical 404. `handleFeedRequest` is the whole handler minus HTTP plumbing (the route is the integrator's).
- Management (`manage.ts`): add feed (validated, probed once, audited with host not URL, audit first), remove feed, create and revoke tokens (audit first), per-workspace limit, tenant checks. Feed URLs live in the Vault only.
- needs_attention: failures are counted per feed (`ical_feeds.failures`); at 3 in a row the connection goes `needs_attention` with a readable reason, the owners get one deduped in-app notice (en, ta draft) and an audit row (`ical.feed_failing`); Test connection re-reads each feed and, if all work, clears the counters so syncing resumes. Tenant isolation: every store call is scoped by tenant and workspace (and connection); tested with identical UIDs in two tenants.
- i18n namespace `ota` (en final, ta machine draft in `_review.json`), registered. Env name `CHANNEL_MANAGER_API_BASE` in `.env.example`.
Tests: Vitest in `channel-manager/__tests__` (mapper, apply semantics, generic adapter and fixtures, availability, time zones, runner end to end with fakes) and `ical/__tests__` (parser, stays, SSRF classification, guarded lookup, fetcher with a fake `https.request`, sync reconcile, failure to needs_attention, export, token handling, management). 153 tests, typecheck clean.
