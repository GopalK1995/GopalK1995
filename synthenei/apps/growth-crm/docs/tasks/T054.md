# T054 · Dashboards and analytics on real data · BUILT, NOT RUN IN A BROWSER

Done:
- Home (`src/app/(app)/page.tsx`) rebuilt. Organising idea: the month as a ruler, pipeline flow against target. Order: decision zone (gap to target readout + things to act on today: first-response SLA breaches, slipped close dates, deals past stage SLA, closing in 7 days, overdue tasks), the configured headline tiles as one ruled row, the month ruler (cumulative won vs target pace vs forecast from weighted open deals) beside a stage-flow list (bar = value, one tick per deal, red = past stage SLA), paid vs organic social, then the charts named in `tenant_config.dashboard.charts`. No KPI strip + table + rail; no card walls.
- Tiles come from `tenant_config.dashboard.kpiTiles` (all 12 catalogue ids), computed from real rows in `analytics/_lib/home.ts`. A reading that cannot be computed is null and shown as No data, never 0. Stage meaning (won/lost/open, probability, SLA) comes from the tenant config; nothing tenant-, brand- or price-specific is in code.
- Charts: Recharts, every one inside `ChartWithTable` (`src/components/charts/chart-table.tsx`): a Chart/Table toggle where the table is a real `<table>` with caption and scoped headers. New `MonthRuler` and `PairedTrend` charts keep gaps as gaps and tooltips say No data. `Kpi` (T007 handover) lost the count-up and shadow and accepts a null value; new `KpiLedger` for the tile row.
- Paid vs organic social side by side (30 days): paid = `campaign_daily_metrics` of meta/linkedin campaigns, organic = the T071 social read model (`loadSocialView`, RLS or labelled demo sample). Measures that do not exist for a side read Not applicable; unknown reads No data. Per-state notes for organic (not connected, needs vendor approval, needs attention, empty, error, denied). `/analytics/social` is untouched and linked from the home panel and the analytics header.
- Attribution (`/analytics`): reads recorded `leads.first_touch_channel` / `last_touch_channel` for real sessions; an untagged lead is its own last row "No touch recorded" instead of being credited to Organic. Demo sessions use the sample leads.
- Viewer variant: same page, counts only: decision rows are text (no record links), rep and account names become Rep n / Account n.
- Real vs demo: demo sessions show a Sample data band and read the mock source; real sessions never see synthetic rows (the old fabricated funnel top steps and the hard-coded "backup check (sample)" chip are gone). A failing optional source gives a partial state naming it; a failing core read (leads, deals) gives the error state naming the source.
- i18n: new `dashboard` namespace (en only; Tamil falls back to English).
- Tests: Vitest `src/components/charts/__tests__/chart-table.test.tsx` (toggle, table semantics, No data vs 0, KpiLedger) and `analytics/_lib/__tests__/home.test.ts` (ruler, flow, decisions, tiles null, paid vs organic, attribution); 19 pass. Cypress written, NOT run: `dashboard/owner-home.cy.ts`, `dashboard/viewer-masked.cy.ts`, `analytics/attribution.cy.ts`.
