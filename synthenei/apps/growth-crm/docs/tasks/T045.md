T045 · Google Business Profile connector + reviews reply UI · BUILT, NOT RUN AGAINST GOOGLE

Done:
- Connector `google-business` under src/lib/connectors/google/business-profile/**, registered in connectors/all.ts. OAuth through the shared Google client (T039 helpers: token refresh with revoked-grant detection, backoff, Vault, selection plumbing), scope `business.manage`. Gate `needs_vendor_approval`: Google grants the Business Profile APIs to approved applications only. Showcase gateway (sandbox token or APP_ENV=demo) never touches the network, refused in production.
- Listing selection: `listGbpLocations` / `selectGbpLocation` (accounts, then locations; the pair must be one Google reports for the user; tenant and workspace checked; both cursors reset; audited).
- Streams: `reviews` (every 2 h, resumable by page token, idempotent on connection + review id) into `reviews`: a re-sync refreshes rating / text / author but never touches reply_draft, reply_status or the approver; unreadable rating or id is rejected, not invented; anonymous reviewers have no name. `performance` (hourly slot, daily): search / maps impressions (desktop + mobile summed), call, website, direction, conversation, booking, food-order counts into `gbp_daily`; 90-day backfill, window ends two days back (Google's lag), trailing week re-read; a metric Google did not report is null, never 0.
- Reply workflow (reply.ts): draft (human text, AI drafter via the `ReplyDrafter` port, or the default template drafter) -> submit -> approve by a named signed-in person -> post. Post re-reads the row and refuses unless it is `approved` with an approver and a draft; editing an approved reply sends it back to draft; approve and post are audited first (audit or nothing); compare-and-set so two clicks cannot both approve; Google refusal marks `failed` (retry needs a fresh approval), a transient error leaves it approved. The 0019 trigger and check constraint enforce the same rules in the database.
- UI: `src/components/reviews` (`ReviewsPanel`, `StarRating`, types). Actions are passed in (server actions are outside the Owns list). Strings in messages/{en,ta}/reviews.json, registered in the i18n registry; `google-business.sandbox` added to integrations.json.
- One shared one-liner: `GoogleRequest.method` in google/shared/api.ts now allows PUT (the reply endpoint is a PUT).
Tests: Vitest src/lib/connectors/google/business-profile/__tests__/gbp.test.ts: mappers against Google's published shapes with synthetic fixtures, the four-API client against scripted responses (URLs, read mask, page tokens, PUT body, 401/403/429/503), resumable idempotent streams, null-not-zero metrics, selection with tenant isolation, the whole approval workflow including the cases that must refuse, registration and env names. The T039 hard-rule scan covers these sources too. Cypress written, NOT run: connectors/gbp-review-approval.cy.ts (needs the page that mounts the panel).
Deviations from plan:
- No page and no server actions (not in Owns): the panel takes its actions as props; the actions are exported functions for the integrator to wrap (see "T045 needs").
- No AI model is wired: the AI path is a port (`ReplyDrafter`); the default is a rule-based template drafter. Nothing in the connector can approve or post on its own.
- Existing owner replies on Google are shown read-only (`external_reply`, optional column); they are not mirrored into reply_status (the trigger forbids starting as posted).
Needs from integrator: see "T045 needs" in docs/migrations-backlog.md (gbp_daily table, optional reviews columns, catalogue row, OAuth redirect URI, env names, server actions, page).
Owner decisions: apply for Business Profile API access (per Cloud project) and the Google OAuth app verification for `business.manage`; which AI provider drafts replies (and whether review text may be sent to it: consent purpose `ai_processing`); which role may approve replies; whether auto-reply for 5-star reviews is ever wanted (not built, would break the human-approval rule).
Unverified: nothing ran against real Google, Supabase, the Vault or a browser. Endpoint paths, the `reviews` v4 base, `orderBy`, the Performance metric enum names and "a zero is an omitted value" follow Google's docs from memory and are untested live; fixtures are hand-written. The gbp_daily upsert and the reviews store are not unit-tested (fakes only). Tamil strings are a machine draft.
