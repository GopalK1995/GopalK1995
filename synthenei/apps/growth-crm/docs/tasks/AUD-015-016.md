# AUD-015 / AUD-016: layout round trips and i18n payload

## AUD-015 (signed-in layout)

Before: `(app)/layout` awaited 5 dependent Supabase calls in series: `my_workspaces` -> `tenant_config` -> `authz.my_grants` -> `workspaces` (tenant id) -> `object_types`.

After, 2 waves, no migration needed:
- wave 1: `my_workspaces` (now also returns the tenant uuid, kept on `Tenant.uuid`).
- wave 2, in parallel: `tenant_config`, `authz.my_grants`, `object_types`. `requireActive()` starts the grants and object-type reads as soon as the workspace is known (`src/lib/authz/grants-fetch.ts`, `src/lib/metadata/nav-types.ts`, both React `cache()`), and `loadPrincipal()` / `loadNavObjects()` await the same promises.
- `requireActive` itself is now request-cached (it was re-run by the layout, the nav loader and `loadPrincipal`).
- `team()`: 3 sequential reads -> 2 (profiles and sales_targets in one wave).
- Authorization unchanged: `loadPrincipal` still fails closed (no client, RPC error, empty result -> `GrantsUnavailableError`); the prefetch never throws, it returns the error as a value so `loadPrincipal` decides. `tenantOfWorkspace` remains the fallback if the tenant uuid is missing.
- Skeletons: `loading.tsx` added for leads, leads/[id], accounts, sales, ai, analytics, settings (the group `(app)/loading.tsx` already covered the rest).
- Not done: the layout still blocks the shell on those two waves (the shell needs the session and nav objects), so the shell does not stream before them. A Suspense-wrapped nav would need the shell split; left for a follow-up. A single RPC (`0025_*`) would cut wave 2 to one call but is not needed to meet "at most 2 waves", so no migration was written.
- Not measured: signed-in latency (no Supabase credentials in the isolated build). The 5 -> 2 wave change is from the code path and unit tests, not a timing.

## AUD-016 (i18n payload, public pages)

Method: isolated copy, `npm ci --ignore-scripts`, `APP_ENV=demo`, no Supabase env, `next build` + `next start`, fetch with identity encoding, brotli/gzip measured locally (type and lint checks were disabled in the copy only; `tsc` and eslint were run separately in the worktree). Script list = unique `<script src>` in the HTML.

| Page | HTML before | HTML after | Scripts before | Scripts after | Script brotli before | after |
|---|---|---|---|---|---|---|
| /login | 196,858 B (40,247 br) | 57,408 B (6,321 br) | 25 | 10 | 333,477 B | 154,207 B (178,880 gzip) |
| /auth/reset | 152,036 B (36,595 br) | 13,015 B (2,893 br) | 30 | 21 | 446,945 B | 403,266 B |

What changed:
1. The root layout no longer renders a client i18n provider (public pages have no client component that reads messages) and no longer imports `brandBootScript` from `components/shell/providers` (a `"use client"` module that dragged the shell, realtime client and charts into every page's client graph). The empty boot script was removed.
2. `(app)/layout` provides only `APP_NS` (common, errors, shell, search, reviews). Section layouts add what their client components use: ai, leads (ai, imports), inbox (ai), import (imports), analytics (social). Server components still use the full catalogue through `getT`.
3. `src/i18n/__tests__/namespaces.test.ts` scans the source: every `useTranslations("x")` must be provided where it lives (including components imported across sections), public routes may not use it, section layouts must wire what `SECTION_NS` declares, and every declared namespace must exist in English and resolve in Tamil (English fills gaps via `messagesFor`).

Open: `/auth/reset` still loads 21 scripts including the realtime and chart chunks. The page itself imports nothing heavy; Next lists the union of the chunks of a shared client module (a lucide icon base reference) for the page. Cause not isolated; try `optimizePackageImports` / `splitChunks` tuning next. `/login` is down to 10 scripts. HTML on /login is still 57 KB, mostly the login page's own persona data. The "every route is dynamic" point (PERF-013) is untouched: the root layout still reads cookies for the locale and tenant.
