Done:
- Connector `linkedin` (src/lib/connectors/linkedin/**, registered in connectors/all.ts), gate `needs_vendor_approval`. OAuth 2.0 through the connector core (scopes r_ads, r_ads_reporting, r_ads_leadgen_automation); tokens in the Vault. `listLinkedInAccounts` / `selectLinkedInAccount` (server action targets) pick the ad account from what LinkedIn says the user can access, register it platform-wide (one account, one workspace) and audit (`linkedin.account_selected`).
- Lead form poll: stream `leads` (every 15 min) reads leadFormResponses of the connection's own ad account (oldest first, resumable offset cursor, 30-day backfill, boundary overlap made harmless by the external link) -> answers keyed through the form definition (cached per form) -> tenant field map (defaults for LinkedIn's predefined questions, object `LeadFormResponse`) -> lead created or matched by E.164 phone / lower email. New lead: source `linkedin`, first/last touch channel linkedin, utm, campaign text and link (stand-in name until analytics learns the real one). Existing person: first touch and source kept, only last touch moves. Idempotent by response id. Consent only from tenant `consent_rules` (field answered yes, or LinkedIn consent id accepted); no defaults, written once per response with `consent.changed`. Test leads are kept and flagged.
- Ad analytics: stream `analytics` (hourly slot, once per IST day after 06:00) -> campaign_daily_metrics by (campaign, day): 30-day backfill, trailing 7-day re-read, spend to paise, INR only unless the tenant sets `fx_to_inr` (else rejected, never guessed), impressions, clicks, one-click leads. Sandbox rows get source `mock`.
- Token expiry: stream `health` (daily) throws CredentialError (-> needs_attention, visible to the owner) when the stored expiry has passed or introspection says inactive; reports days left and missing scopes otherwise. A 401/403 from any call is a CredentialError too, so a missing product grant also lands in needs_attention. Refresh uses the framework default (LinkedIn issues refresh tokens only to approved partners).
- Tenant isolation: a response is processed only when its owner is THIS connection's ad account (else rejected `account_mismatch`, nothing written); ad accounts are unique platform-wide (SQL in backlog); selection of an account owned by another live connection is refused; another workspace's connection looks missing.
- Sandbox / showcase: mock gateway (token `linkedin-mock-token`, or APP_ENV=demo without credentials), no network, refused in production. `LINKEDIN_API_BASE` points the client at a stub. Strings: namespace `linkedin` (en, ta draft) in src/i18n/registry.ts; `linkedin.sandbox` in integrations.json. Env names in .env.example, no values.
Tests: unit src/lib/connectors/linkedin/__tests__ (response/form parsers from recorded-shape fixtures, mapping, consent rules, lead create/match/idempotency/isolation, poll cursor + pagination, analytics normalisation incl. currency, window plan, stream, token expiry/health, REST gateway requests/headers/errors/backoff, account selection + isolation + audit, connector def).
