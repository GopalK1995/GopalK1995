Done:
- `webhook.deliver` handler (queue `webhook_out`, registered by one import line in `src/lib/jobs/handlers/index.ts`): refetches the event, applies the endpoint's event patterns and filters, builds the envelope (`id, type, created_at, org_id` = tenant alias, `workspace_id`, object ids, actor, `data` with safe fields only), signs with Standard Webhooks (`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256>`; secret `whsec_<base64>`), sends once per message and logs status, attempt, response code, latency and a 2 KB scrubbed excerpt to `webhook_deliveries`.
- Retries are scheduled by the handler itself on the C10 schedule (30 s, 2 m, 10 m, 1 h, 6 h, 24 h, +/- 20 % jitter; 7 attempts, then `dead`) by re-enqueueing `attempt+1` with a delay. Auto-disable at 20 consecutive failures and no success for 5 days: endpoint paused (`disabled_reason = auto_failures`), in-app notification to active owners, `webhook.endpoint.disabled` event (best effort). Idempotent: redelivery of a finished event or of an attempt that already ran is acknowledged without sending; receivers can dedupe on `webhook-id` (event id, same across retries and replays).
- SSRF guard on every attempt (`src/lib/webhooks/send.ts`): `assertPublicHttpsUrl` with a fresh DNS resolution each time, then the connection is pinned to the validated address (custom `lookup`), no redirects followed (3xx = failure), 10 s timeout, response read capped at 64 KB. A blocked destination is not retried.
- PII: `data` is stripped of personal keys (word-based match, field names dropped from `changed_fields` too) unless the endpoint opted in AND the creator still holds `pii.read` at send time (checked on every delivery, custom roles fail closed). Field masks are supported by `buildEnvelope({ masked })`. Oversized bodies (> 256 KB) are replaced by ids only with `data_truncated`.
- Settings UI `/settings/webhooks` (list: create/edit/pause/resume/delete, event picker from the catalogue grouped by domain, optional filters, PII opt-in, secret shown once with copy, rotate with a 24 h two-signature grace window, test-ping button) and `/settings/webhooks/[id]` (delivery log, status filter, owner-only replay with confirmation, audited before it runs). States: empty, loading skeleton, error with source, partial (log capped note), permission-denied, support-session blocked, org policy off (`allow_webhooks`, button disabled with reason), replay disabled with reason for non-owners. Demo shows labelled sample endpoints and deliveries, simulated test ping (no network), writes nothing.
- Secrets: stored only in Vault (`vault_put_secret`), only secret ids in rows, never selected into the client view (`toView`), returned once from create/rotate; logs carry ids, attempt, kind and status only (test asserts no secret, body or URL in logs). Housekeeping job `webhook.housekeeping` (queue `maintenance`) deletes deliveries older than 30 days and retires previous secrets after the grace window.
- i18n: `messages/en/webhooks.json`, `messages/ta/webhooks.json` (draft, `_review`). Audit actions: `webhook.endpoint_created|updated|paused|resumed|deleted`, `webhook.secret_rotated`, `webhook.delivery_replayed`.

Deviations from plan:
- Plan names the Cypress folder `webhooks/` and a local echo server via `cy.task`; the task brief says `webhooks-out/`. A local echo server cannot work end to end because the SSRF guard (correctly) refuses localhost; real-delivery specs need a PUBLIC https receiver in `CYPRESS_WEBHOOK_ECHO_URL` and skip without it. The delivery path is covered by unit tests against a fake transport.
- Subscription options (PII opt-in, filters) have no column in 0015, so they are stored as reserved entries in `webhook_endpoints.event_types` (`@pii`, `@filter:<field>=<a|b>`). They never match an event type, so the T019 fan-out and the T025 REST hooks ignore them. Source for a later migration to an `options jsonb` column.
- No per-type serializer that refetches the object (CONTRACTS C10 text): `data` is the event's own non-PII `data` (changed_fields, before, after), sanitised again. PII is therefore never read, rather than read and masked. Filters match `data.after[field]`, `data[field]` or `object_type`.
- Retry timing is owned by this handler (re-enqueue with delay) instead of the drainer's 5 s doubling backoff; the original message is acknowledged after the retry is queued.
- `last success` for auto-disable is derived from the latest `succeeded` delivery row (no column); `consecutive_failures` is read-modify-write (slight undercount possible under concurrent failures).
- Demo gate uses `integrations.manage` (legacy fixture has no `webhooks.manage`), as in api-keys.
