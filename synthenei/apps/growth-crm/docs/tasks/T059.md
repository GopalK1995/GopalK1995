- Accessibility pass (this session): ran `cypress/e2e/a11y/all-routes.cy.ts` (axe-core, 29 routes + command palette + the /forbidden denied state) and `cypress/e2e/mobile/390.cy.ts` (no-horizontal-scroll at 390px across 18 routes + drawer + command palette + 4 Tamil-locale routes) repeatedly against the actual dev server, found and fixed seven distinct real bugs:
  - `src/components/ui/avatar.tsx`: every tone's text color changed from the raw `text-chart-N` hue to `text-ink` — a chart color at full strength paired with its own light-opacity tint as the text failed color-contrast; the background tint still varies per tone for visual distinction, only the text pairing needed to change.
  - `src/components/shell/switcher.tsx` + `src/components/shell/shell.tsx` (WorkspaceSwitcher, UserMenu, CommandChip): axe's `label-content-name-mismatch` (WCAG 2.5.3 Label in Name) flagged all three. Root cause, found by reading axe-core's actual tokenizer (`node_modules/axe-core`, `labelContentNameMismatchEvaluate`/`isContiguousSubsequence`): adjacent JSX sibling `<span>`s render with zero literal whitespace between them (only CSS `gap`), fusing their text into single unsplittable tokens (e.g. `"lawsometamil"`) that can never match a separately-worded aria-label — and decorative `aria-hidden` initials (Monogram, Avatar) still count as "visible text" for this specific check despite being hidden from the accessibility tree. Fixed by adding literal `{" "}` between every adjacent text-bearing sibling, and for CommandChip/UserMenu extending the `aria-label` to literal-match the now-correctly-spaced visible content (including the keyboard-shortcut hint and avatar initials). For WorkspaceSwitcher, removed the hand-maintained `aria-label` entirely in favor of native content-derived naming (can't drift out of sync since it IS the visible text) plus an `sr-only` span for the "Switch workspace" action hint and the collapsed (icon-only) sidebar state's fallback name.
  - `src/app/(app)/pipeline/_components/board.tsx` + `src/app/(app)/inbox/_components/inbox-app.tsx`: added `tabIndex={0}` to two scrollable regions (the stage-share strip, the message list) that had no keyboard access (`scrollable-region-focusable`).
  - `src/components/ui/data-table.tsx`: same fix (`tabIndex={0}`) on the shared `DataTable`'s horizontal-scroll wrapper — used by nearly every list page in the app, so this one fix covers all of them (only surfaced on `/settings/audit`, where the table is wide enough to actually overflow at the tested viewport).
  - `src/app/(app)/settings/objects/_components/objects-view.tsx`: an inline link only underlined on hover, relying on color alone to be distinguishable from surrounding body text at rest (`link-in-text-block`); made the underline permanent.
  - `src/components/ui/skeleton.tsx` (`PageSkeleton`) + `src/components/fields/custom-fields-panel.tsx` (`CustomFieldsSkeleton`): both used `aria-label` on a bare `<div>` with no ARIA role, which is invalid (`aria-prohibited-attr`) — every other `loading.tsx` in the codebase already uses `role="status"` for exactly this reason; added it to these two outliers.
  - `src/app/(app)/settings/email/_components/email-settings.tsx` (3 occurrences) + `src/app/globals.css`'s `.state-info`: two separate color-contrast failures. `text-warn` (the bright, background/icon-oriented warn color) was used directly as body text instead of the existing darker `text-warn-ink` — changed to the latter. `.state-info` had no darker "-ink" text variant the way `.state-warn` already did (`globals.css` already special-cases `.state-warn { color: var(--warn-ink) }`); added `--info-ink` to `tokens.css` (`oklch(0.38 0.09 220)`, following the same pattern as `--warn-ink` relative to `--warn`) and applied it the same way, removing the conflicting later `color: var(--info)` rule for `.state-info` that would otherwise have won the cascade.
- Also fixed, project-wide: `cypress/support/e2e.ts`'s `uncaught:exception` filter only matched the production-minified React hydration error string; under `next dev` the app throws the full unminified message instead (same pre-existing root-layout hydration quirk noted in T058's task doc), so every e2e spec using `cy.loginAs` was silently failing on this unrelated issue. Broadened the filter to match both forms — this is what let these two suites (and T058's) actually run at all in this environment.
