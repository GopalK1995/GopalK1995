T048 · Zoho CRM + HubSpot (two-way sync and migration import) · MERGED (sha in final message)
Done:
- Shared engine `src/lib/connectors/zoho/engine/**` (HubSpot imports it; move to `connectors/core/crm-sync` when allowed): field-level three-way merge (`conflict.ts`), field map to columns (`map.ts`), import / pull / push / reconcile (`run.ts`), glue (`kit.ts`), options (`options.ts`), Supabase store on the service role (`store-supabase.ts`).
- Zoho CRM (`zoho-crm`): OAuth on India (`accounts.zoho.in`) by default; data centre stored per connection (`region`, set via `finishZohoSetup`: in, us, eu, au, jp, ca, sa, cn); v6 gateway (COQL by Modified_Time, records API); Zoho's 200-with-error token answers handled; notifications via `actions/watch` renewed daily, channel id derived from the connection, body token re-checked. Streams pull, push, health.
- HubSpot (`hubspot`): OAuth (framework refresh), v3 gateway (search by last-modified, paced 5 req/s, 10k cap handled by window restart, batch read, create, update), webhooks (v3 signature at the edge, portal id must match), `finishHubspotSetup` binds portal and signing secret. Contacts land as leads (or contacts via `contact_target`).
- Initial import uses the T034 pipeline: field map, then `planImport` (clean, validate, dedupe vs workspace and in-run); duplicates are linked (skip keeps CRM record, merge writes vendor values). Reasons counted without PII. Resumable cursor per object in dependency order; `import_since` limits backfill.
- Incremental two-way sync with `external_links` + `integration_field_maps`: per-column hashes of both sides at last sync (JSON in `content_hash`); a column changed on one side travels, only a column changed on both sides is a conflict, settled by `direction` / `conflict_owner`. No echo loops. New CRM records are pushed only if `push_new` is on; vendor duplicates are linked.
- Safety: workspace scoping everywhere; field-map rows can never write id/tenant/workspace/timestamps/external_ids; no nulls into required columns; deletes never propagate; one record's vendor rejection affects only it; unmapped stage rejects the deal; Zoho COQL inputs validated.
- Audit: row triggers audit writes; setup/options actions audit first (no audit, no change); every run writes `sync_runs`. Backoff: shared client (429/5xx, Retry-After). Token expiry: refresh before runs and by the scan; dead refresh token or 401/403 = needs_attention, later runs skipped.
- Strings: namespace `crmSync` (English, Tamil falls back) in the i18n registry; `zoho-crm.sandbox`, `hubspot.sandbox` in integrations.json; env names in .env.example; both connectors in connectors/all.ts.
Conflict table (column): direction / conflict_owner
| in | only vendor changed: pull | only CRM changed: kept, never pushed | both: vendor wins |
| out | ignored | push | CRM wins |
| both | pull | push | crm -> CRM; external -> vendor; last_write -> newer timestamp (tie/unknown -> CRM) |
Defaults: all rows `both`, owner `crm` (DB default).
Tests: unit in zoho/__tests__ and hubspot/__tests__ (conflict table, engine against fakes, gateways with fixtures, token refresh, webhooks, watch renewal, setup/options, framework runner incl. needs_attention). Cypress written, NOT run: connectors/zoho-import.cy.ts, connectors/hubspot-sync.cy.ts. typecheck, lint, Vitest only.
