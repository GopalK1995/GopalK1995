T056 · Global search + command palette · MERGED (sha in final message)
Done:
- Palette (`src/components/command/command-palette.tsx`, cmdk inside a Radix dialog): Ctrl/Cmd+K toggles it anywhere (also while typing), or `openCommandPalette()` / the `gcrm:open-palette` window event. One line registers it in `src/components/shell/shell.tsx` (`<CommandPalette />`).
- Groups: Recent (per browser, user and workspace, max 8, filtered to the types the server still allows), Records (leads, accounts, contacts, custom-object records), Actions, Go to (pages from `navFor(role, tenant, objects)`, so only pages the role may open and custom objects the viewer may read).
- Actions are decided on the server with the authz engine (`src/lib/search/actions.ts`): New lead (`leads.create`), Log call (`activities.write`), New task (`tasks.write`), Import (`leads.import`). A viewer gets none. They only navigate (`/leads?new=1`, `/leads?log=call`, `/tasks?new=1`, `/import`); the palette writes nothing.
- `GET /api/search?q=` (`src/app/api/search/route.ts`, logic in `src/lib/search/handler.ts`): 401 without a session, 403 for cross-site fetches, 30 requests per 10 s per user and IP (429 with Retry-After), input sanitised (control and zero-width characters, every PostgREST and LIKE metacharacter removed, 2 to 64 characters; one character answers `tooShort`), no-store, 500 never echoes the cause (request id only). An empty `q` is the bootstrap call: permitted actions and searchable types.
- Real sessions query through the user's own client (`dbForRequest`), never the service role, so RLS decides. Viewers without `pii.read` read `v_leads_masked` and `v_contacts_masked`, and only the masked columns are searched (names as initials; a full name finds nothing). Every row is also re-checked with `can()` (own and team scope). Custom objects: title plus text-like `is_searchable` fields; PII fields are not searched without `pii.read`, and a PII primary field shows a masked title. A source that fails marks the answer `partial` and the others still show.
- Demo sessions search the in-memory dataset with the same rules (reps only their own leads, initials for viewers, the labelled example object). Contacts are not in the demo dataset.
- States: loading (spinner and "Searching" status), empty, too short, error with Try again, rate limited, partial. Keyboard: arrows, Home/End, Enter, Esc, loop; focus moves to the input on open and back to the page on close (Radix); the dialog is labelled and described; fits 390 px.
- i18n: namespace `search` (`messages/{en,ta}/search.json`, registered in `src/i18n/registry.ts`, Tamil flagged in `messages/ta/_review.json` and `_review/search.json`). Lead and account headings and the "New {noun}" action come from the tenant vocabulary.
Tests: Vitest in `src/lib/search/__tests__/{sanitize,recent,handler,actions,demo,engine}.test.ts` (a fake PostgREST builder asserts tables, columns, filters, workspace scope, masked views, PII handling, partial failures) and `src/components/command/__tests__/command-palette.test.tsx` (open and close keys, actions, search, sanitised query, empty, loading, error and retry, 429, recent filtering, Tamil, masked label). Typecheck and lint clean. Cypress written, NOT run: `cypress/e2e/search/{palette,no-foreign-results}.cy.ts`.
Deviations: `src/components/ui/command.tsx` (T016) is not used because it filters client-side; cmdk is used directly. Contacts link to their account page (`/contacts` when none) because there is no contact detail page.
Needs from integrator: see "T056 needs" in `docs/migrations-backlog.md` (trigram indexes for the extra columns and searchable custom fields, `?new=1` and `?log=call` handlers on the lead and task pages, T059 top-bar chip calling `openCommandPalette()`).
