Done:
- POST/GET `/api/hooks/[connector]/[connection]` (route per card/CONTRACTS C10; `[connection]` = integration id, a v4 UUID, used as the unguessable per-connection token). Logic in `src/lib/connectors/verify/receive.ts`: IP + per-token rate limit (429 + Retry-After), connection resolve (unknown, malformed, wrong connector, disconnected, demo, mock-in-production all return the same bare `404 {"ok":false}`), 1 MB limit (413), signature check on the RAW body with the scheme the connector maps to, insert into `webhook_inbox` (unique `(connector_id, provider_event_id)`, id = `<connection>:<vendor event id or body sha256>`), enqueue `connector_inbound` `{inbox_id}`, answer 200. Nothing processed inline. Duplicate = 200 `{ok:true,duplicate:true}`, no second enqueue. Enqueue failure = 503 and the row is removed so the vendor retry is not a dup.
- Verifiers (one file each, `verify(raw, headers, secret, opts)`, `timingSafeEqual`): meta (X-Hub-Signature-256), razorpay, slack (v0, 5 min), calendly (t/v1, 3 min), calcom, google-pubsub (RS256 JWT vs Google JWKS, aud and optional service-account pin), mailchimp (`?k=` secret), hubspot v3 (5 min), zoho, standard (Standard Webhooks for zapier/make/mock; any listed v1 may match). Connector -> scheme map and secret picking in `verify/index.ts`.
- Handshakes: Meta GET hub.challenge (token from the connection's Vault bundle `verify_token` or env `META_WEBHOOK_VERIFY_TOKEN`; bad token 403; non-Meta 404); Slack `url_verification` answered after the signature check, not stored.
- Bad signature: 401 `{"ok":false}`, logged as connector + connection id only (never body, headers, secret), row stored with `signature_ok=false, body=null`, capped at 30 stored rows/min/connection.
- Consumer `verify/process.ts`: `connector_inbound` wildcard handler; loads the row, runs `ConnectorDef.webhook.verify` (parse) and `handle` per event with a SyncContext, writes a `sync_runs` row (kind webhook), marks `processed | failed | ignored`. Idempotent (processed/ignored rows skipped); failures keep a scrubbed error and stay visible as `failed` (also after the last attempt = dead letter); `replayInbound()` requeues a verified row.
Tests: unit `src/lib/connectors/verify/__tests__` verifiers (21), receive (14), process (4+) = 40 passing (Standard Webhooks reference vector and Slack docs vector are real published vectors; the other schemes use vectors built from the documented construction, no vendor-recorded fixtures); full `vitest run` 49 files / 653 tests passing (run with `--pool=threads`; the default forks pool timed out starting workers on this loaded machine). typecheck clean, lint 0 errors (97 warnings, none mine).
