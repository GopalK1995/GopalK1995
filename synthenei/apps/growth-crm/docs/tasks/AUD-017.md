# AUD-017: visible keyboard focus and 3:1 form-control borders

Sources: A11Y-001/003/004/005/006, COMP-005, DSYS-017/025/026, UI-014.

## Tokens (src/styles/tokens.css, src/app/globals.css)
- `--focus-ring-width: 2px`, `--focus-ring-offset: 2px`, colour `--ring`. One utility `focus-ring` (outside, offset 2 px) and `focus-ring-inset` (inside the box, for controls flush against an overflow-hidden parent: tab lists, nav links, dialog search inputs). The global `:focus-visible` base rule uses the same tokens.
- `--field-line: oklch(0.6 0.011 90)` (Tailwind `border-field-line`), the resting border of every form control. `--line` / `--line-strong` stay decorative dividers.
- One shared class: `src/components/ui/field-styles.ts` (`fieldBase`, `fieldCls`). Used by `Input`, `Textarea`, `Select` trigger and the migrated local copies.

Asserted by `src/styles/__tests__/focus-and-field-contrast.test.ts` (3:1 floor for all of the above).

## Fixed
- Shell nav links, shared Tabs triggers and panels, Segmented control, settings tab panels (`tabIndex=0`), social chart marks (`g[role=button]`), integration cards/rows, branding colour range input, command palette inputs: bare `outline-none` replaced by `focus-ring` / `focus-ring-inset`.
- All text-input/select/textarea class strings that used `outline-none` plus `border-line-strong` now use `focus-ring` plus `border-field-line`; the identical 36 px copies (and the billing/admin billing/leads `field` copies) now import `fieldCls`. Checkbox, Switch and Radio borders also use `--field-line`.
- Guard test: `outline-none` must be paired with `focus-ring`, `focus-visible:ring` or `focus-visible:outline`, or be on the documented allowlist in the test (dialog/sheet/popover/drawer containers with programmatic focus, menu items that show focus through `data-[highlighted]`, the skip-link target `main`).

## Not done / listed
- Local `field`/`inputCls`/`sel` strings with non-standard sizes (h-8, h-10, text-13/14, number inputs) still exist as separate constants; they now use the same border and ring tokens but are not yet one class (follow-up AUD for the form-input consolidation, which depends on this task).
- Menu and listbox items keep `outline-none` with the `data-[highlighted]` fill (0.96 vs 0.995 lightness, below 3:1). Listed as follow-up; not changed here.
- Pre-existing paired `focus-visible:ring-2 focus-visible:ring-ring` rings (box-shadow, no offset) were left as is: compliant, visually slightly different from `focus-ring`.
- Not verified in a real browser (no deploy, no screenshots); verified by typecheck, eslint and Vitest only.
