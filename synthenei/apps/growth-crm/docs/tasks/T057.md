**Major finding — not a T057 bug, but a real one, surfaced for the first time by this suite**: `node scripts/gen-authz-matrix.mjs --check` cross-checks the TS engine's `systemGrants()` (`src/lib/authz/system-grants.ts`, the grants demo-mode sessions actually use — see `src/lib/authz/principal.ts:1,19`) against the SQL seed's `SYSTEM_ROLES` (`src/lib/authz/catalog/system-roles.ts`, what real sessions get via the `authz.my_grants` RPC). These disagree on **56 role×permission grants**, driving divergent allow/deny on **489 of the 5,436 matrix cells**. The root cause is already acknowledged in the code: `system-grants.ts` line 1-3 reads *"TEMPORARY HOME: T001 owns catalog/system-roles.ts (the SQL seed source). When that file lands, swap `systemGrants` to read it"* — that swap was never done. Concretely, in demo mode today: **owner** is missing grants for `billing.manage`, `billing.read`, `members.invite`, `roles.manage`, `webhooks.manage`, `api_keys.manage`, `audit.read`, `comments.write`/`.moderate`, `records.share`, `teams.manage`, `fields.manage`, `objects.manage`, `layouts.manage`, `notifications.manage`, `inbox.assign`, `tasks.assign`, `views.share`, `events.read`, `messages.send_email`/`.send_whatsapp`, `accounts.delete`/`.merge`, `contacts.delete`, `deals.delete`, `leads.delete`, `audience.export` (28 permissions); **sales_manager** is missing 15 similar admin-ish grants; smaller sets for **sales_rep**, **marketing**, **data**, **viewer** (full list and per-role detail in the SQL file's header comment, lines 14-76). A few go the other way (TS grants something SQL doesn't — `sales_rep`/`viewer` `contacts.read` at `all` vs SQL's narrower `own`/`(none)`, `marketing`/`data`/`sales_manager` holding `analytics.write`/`ai.toggle`/`org.admin`/`integrations.manage` in TS but not SQL). This is squarely **out of scope for T057 to fix** — `system-grants.ts` belongs to T003 (already merged); T057 only owns the test suite that found this. The matrix itself asserts against the SQL-side prediction (the better-grounded source, generated from the original legacy `CAN`/`PAGE_ACCESS` matrix) and tags every affected cell `[KNOWN TS-demo vs SQL divergence]` in its description rather than silently hiding or "fixing" the fixture to paper over it.
