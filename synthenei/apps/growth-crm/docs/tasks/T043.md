T043 · Outlook / Microsoft 365 connector (mail + calendar over Graph) · BUILT, NOT RUN AGAINST MICROSOFT

Done:
- Connector `outlook` under src/lib/connectors/microsoft/**, registered in connectors/all.ts. One multi-tenant Entra ID app (authority `common`), delegated scopes `offline_access User.Read Mail.Read Mail.Send Calendars.Read`, code + PKCE through the shared OAuth start/callback routes. Gate `needs_vendor_approval` (publisher verification). Showcase gateway (sandbox token or APP_ENV=demo) never touches the network, refused in production.
- Token handling (token.ts): Microsoft rotates refresh tokens, the new one is stored; `invalid_grant` / `consent_required` / `interaction_required` / 401 = CredentialError so the framework flips the connection to `needs_attention` (never silent); 5xx / 429 / network = transient. Graph 401 / 403 / no-mailbox also map to CredentialError (errors.ts); 410 = delta restart.
- Streams (sync.ts) over Graph delta queries, resumable by next link, incremental by delta link, idempotent on the Graph id: `inbox` and `sent` (30-day backfill, then incremental), `calendar` (-30 / +180 days into `calendar_events`, deletions cancel the row we hold, a cancelled row is never resurrected, window renewed every 60 days), `subscriptions` (hourly). Mail is stored ONLY when the sender (inbound) or at least one recipient (outbound) is a known lead / contact of the workspace; everything else is skipped and counted, never stored. Subject plus Graph's 255-character preview only, no full bodies, no attachments. Unreadable rows are rejected with a reason, not invented. Event times need UTC (we send `Prefer: outlook.timezone="UTC"`); another zone is rejected, not guessed.
- Send (actions.ts `sendOutlookMail`): plain text only, 1..10 recipients, every recipient must be a known lead / contact of the caller's workspace (the refusal does not say which), a lead without consent for the purpose blocks it, audit first (audit or nothing), token refreshed first, tenant / workspace checked (a foreign connection looks missing). The sent copy comes back through the `sent` stream, so nothing is recorded twice.
- Change notifications: `subscriptions` stream creates inbox, sent-items and events subscriptions (lifetime 4200 min, Graph cap 4230), renews anything with under 12 h left, recreates one Graph dropped (404), records a refused one as `status: error` without failing polling, reports `no_public_url` when APP_BASE_URL is not a public https URL. The per-connection `clientState` (random, 32 bytes) lives in the Vault as the connection's webhook secret. `subscribeOutlook` is the audited on-demand action. Receiver: Graph's `validationToken` handshake is answered as text/plain 200 (strict token shape check, only for a known connection, nothing stored); every notification of a delivery must carry the connection's clientState (constant time) or the whole delivery is 401. The consumer fetches the changed item with our own token (lifecycle events: `reauthorizationRequired` renews now, `subscriptionRemoved` / `missed` are covered by the hourly stream and polling).
- Admin consent for firms (consent.ts): `buildAdminConsentUrl` (tenant id, verified domain or `organizations`; path injection refused) and `parseAdminConsentReturn` (state, grant flag, tenant GUID). Pure; the route is the integrator's (see "T043 needs").
- Outside Owns (the registrations the receiver needs): `verify/index.ts` gets the `graph` scheme and `outlook: "graph"` (one import, one type member, two map entries) and `verify/receive.ts` gets a 2-line handshake branch for that scheme. Also `.env.example` names and `outlook.sandbox` in messages/en/integrations.json.
Tests: Vitest src/lib/connectors/microsoft/__tests__/outlook.test.ts: message / event / notification mappers against Graph's published shapes with synthetic fixtures; the handshake and clientState verifier, including through the real `receivePost`; the Graph client against scripted responses (URLs, headers, retry-after, 401 / 403 / 410 / 404, foreign links refused, plain-text send); streams (known contacts only, tenant isolation, resume, delta, 410 restart, calendar cancel and no-resurrection); subscriptions (create, 12 h renewal, recreate, refused, no public URL, Vault clientState); token refresh and the framework needs_attention path; the send path (unknown recipient, consent, audit-first, tenant isolation, validation, live and Showcase); admin consent; registration, env names, and a scan that no tenant / brand / URL / GUID / secret is in the sources. Cypress written, NOT run: connectors/outlook-gated.cy.ts.
