T030 · Custom fields: admin editor + runtime renderer · MERGED (sha in final message)
Done:
- Admin editor at `/settings/fields` (fields.manage): per object (lead, deal, account, contact, task, custom objects) create, edit, reorder (up/down buttons), retire and restore. Types: text, long text, number, currency (INR, stored as rupees), date, datetime (entered in IST, stored as UTC), single and multiple choice with coloured options, yes/no, url, email, phone (E.164), person, link to a record. Required, unique, default, PII, searchable, filterable, section, help, labels en/ta, validation (min, max, max length, pattern), view and edit roles per field (stored in `options.access`), optional extra edit permission (`editable_perm`). Org limit from `org_admin_policies.max_custom_fields`. Retire is hide-and-keep (`archived_at`); there is no hard-delete path. Removing an option retires it (`archived: true`, kept in `options.choices` so stored values stay valid).
- Every change: guarded write (optimistic token = `updated_at`, stale = conflict), audit row (`fields.created|updated|restored|reordered`; `config.field_retired` and `config.field_options_retired` need a reason of 8+ characters and are audited BEFORE the write, fail closed), `metadata.changed` event. Demo sessions validate and return the demo notice, never touch Supabase; demo shows labelled "Example" fields.
- Runtime: `src/components/fields/` has `FieldInput`, `FieldValue`, `FieldFilter`, `fieldColumn`/`fieldColumns`/`fieldFilterDefs` (DataTableV2 and FilterBar), `<CustomFields object record/>` (server) and `CustomFieldsDisplay` (read-only), `CustomFieldsPanel` (client: read view, Edit mode, changed-keys-only save with the record version, conflict banner with Reload, inline issues with focus, empty/denied/hidden-count states, keyboard operable). `loadListFields(object)` returns visible columns and a `maskRow` for list pages.
- Masking is server-side: `prepareCustomFields` and `listFieldsFor` remove masked keys and strip access internals before props are serialised (PII without `pii.read`, `viewRoles`, read-grant `fieldMask` `custom.<key>`; users with fields.manage always see). Writes re-check per-field edit permission (`editRoles`, `editablePerm`, record write) and answer unknown, retired and hidden keys identically.
- Validator `src/lib/metadata/validate.ts` mirrors `metadata.check_value()` and `validate_custom()` with the same messages (`custom field "k" must be a number`), plus a coercion step (E.164, rupees, IST, day-first dates). Filters use the public API grammar (`filter[custom.key][eq|neq|in|contains]`); column ids `custom.<key>`; saved views drop retired fields on load.
- i18n: `messages/{en,ta}/fields.json` (ta is a partial draft, `_review: true`, keys listed in `messages/ta/_review/fields.json`, untranslated keys fall back to English). Nouns come from `vocabFor` via `objectNoun`.
Tests: unit 192 passing in 9 files (`src/lib/metadata/__tests__/{validate,access,admin,save,filters,strings}.test.ts`, `src/components/fields/__tests__/{fields,actions}.test.ts(x)`, `src/app/(app)/settings/fields/__tests__/actions.test.ts`); full `npm run test:unit` 847 passing, 1 timeout in `src/lib/jobs/__tests__/route.test.ts` under load that passes alone (5/5); typecheck clean; lint 0 errors (97 existing warnings, none in T030 files). Deviations from plan:
- Concurrency token for field edits is `field_defs.updated_at` (the table has no `version` column); `object_types.schema_version` is bumped by the DB trigger. Reorder writes are unversioned.
- No permanent delete of a field at all (card: never hard-delete a field with data). Retire/restore only.
- "Has data" counts (type lock, option retire reason) are RLS-limited to rows the admin can read, so zero means none visible to them, not proof for other workspaces.
- Per-field visibility is stored in `options.access` and `editable_perm`; custom roles (T017) are not listed in the role pickers, only the six system roles.
- Cypress specs use label/role selectors (no test ids in the editor); only `data-testid="custom-fields"` exists, on the record panel.
