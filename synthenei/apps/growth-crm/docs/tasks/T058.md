- Fixed in this session: `cypress/support/e2e.ts`'s `uncaught:exception` filter only matched the production-minified React hydration error string (`Minified React error #418`); under `next dev` the app throws the full unminified message instead, so every e2e spec using `cy.loginAs` has been silently failing on an unrelated, pre-existing root-layout hydration mismatch (`src/app/layout.tsx`'s manual `<head>` + inline boot script colliding with Next's own head management on client hydration) regardless of what the spec actually tested. Broadened the filter to match both forms. This is a project-wide fix, not scoped to T058 — it's what let any demo-mode Cypress spec run at all in this environment for the first time.
- Corrected two wrong assumptions in `support-session-confined.cy.ts` after tracing actual behaviour in `src/middleware.ts` / `src/lib/auth/context.ts` (`resolveHint`): the `?ws=` deep-link switch is explicitly skipped for platform admins, so it is not a real access vector for this role — the original spec asserted `403` on it, which doesn't match reality. With no support session, `resolveHint` returns null and middleware redirects (307) to `/admin` — safe, never reaching business data. With an active session on workspace A, `resolveHint` binds strictly to `support.ws` and ignores `?ws=` entirely, so a request naming a foreign workspace returns `200` — but serving A's own data, not the foreign tenant's. Rewrote both assertions to check the real isolation guarantee (redirect destination / absence of foreign vocabulary in the body) instead of the wrong status code.
- Also fixed: both form interactions in that spec (start session, end session) were racing the same root-layout hydration remount — it regenerates the whole tree once on first paint, briefly detaching/remounting form controls, so a click or type landing in that window silently no-ops (the "start" interaction already had a wait; the "end" interaction didn't, so `endSupport()` never fired and the cleanup step always timed out). Added matching settle waits before both.
